## 2. 验收总体结论

**有条件通过。**

Phase 1 核心链路已经可演示：

- 代表主状态 12 值、服务商主状态 12 值均已进类型与种子，列表可筛、详情可切。
- `REP-001~008`、`VND-001~006`、`SET-001~008` 三套函数存在，活动/项目/结算校验弹窗能打出 `PASS / BLOCK / MANUAL_REVIEW` 与规则表。
- 登录三角色隔离：服务商仅见 `DEMO_PROVIDER`；合规可见完整证件/账号，销售与服务商脱敏。
- 双门槛成立：`approve()` 在无有效授权时只落到「合格」，不能「启用」；服务商无已生效合同只落到「准入通过」，不能「可合作」。

未达标，必须在整改中关闭：

| 口径 | 数量 | 含义 |
|---|---:|---|
| 22 条验收标准 | **11 通过 / 6 部分通过 / 5 不通过** | 见 §3。不通过集中在：冻结未联动活动、收款主体未校验、风险事件未关联阻断、同人终审未拦截。 |
| 14 个数据实体 | **6 个缺失** / 4 个主键不规范 / 4 个可用 | 见 §4。缺 `mah`、`rep_training`、`vendor_due_diligence`、`performance_acceptance`、`approval_instance`、独立 `audit_log`。 |
| 跨实体关联 | **全部按名称而非主键 ID** | `provider` 存公司名；`representatives: string[]` 存姓名；`relatedRep` / `relatedVendor` 存姓名；合同 `serviceScope` 为拼接串。 |
| 编号 | 种子格式与运行时生成器分裂 | `AUTH-R-${Date.now()}`、`ZR-{年}-{100+n}`、`SQ-2026-{40+n}` 与 seed 的 `AUTH-R-001` / `ZR-2025-0018` / `SQ-2026-001` 不一致，且授权同时存在 `id` 与 `authNo` 两套号。 |

结论：可以继续给业务演示「先准入、后活动」；不能声称已满足第 10 章全部验收，更不能声称数据模型已对齐第 7.1 章。

### 9.3 关键状态机走查路径

1. **代表准入双门槛：** 草稿缺件提交失败 → 补齐提交审核中 → 合规通过变合格 → 授权待审 → 授权通过变启用 → 活动校验 PASS。
2. **代表冻结三级：** 启用 → 冻结（活动被标不可执行）→ 整改中（缺整改措施无法进入复核）→ 复核中 → 发起人/第一合规不能点终审 → 第二人解冻回启用。
3. **授权版本链：** 启用代表变更区域 → 新版本待审 → 通过后旧版 superseded → 审计可见 V1/V2。
4. **备案核验：** 单条无结果 → 冻结或失效；批量任务全部待核验，不能一键有效。
5. **服务商准入：** 缺选聘不能准入；低风险链文案+实例步骤；合同草案 → 准入通过 → 标记生效 → 可合作。
6. **高风险例外：** 瑞康达无三必填点准入失败；填三必填后才进例外审批。
7. **复审存量：** 康晟复审中，新增项目 BLOCK，存量结算 MANUAL_REVIEW。
8. **结算硬拦：** 无项目 / 验收不通过 / 户名不一致 / 未结案高风险分别命中 SET-003/004/006/008。
9. **角色：** 销售发起、合规终审；服务商只见本企业；证件脱敏。
10. **唯一性：** 用已有身份证号新建代表失败；用已有信用代码新建服务商失败。
