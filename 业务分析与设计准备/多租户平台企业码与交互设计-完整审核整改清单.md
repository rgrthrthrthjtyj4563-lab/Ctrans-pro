## 四、平台运营完整业务流程

### 4.1 标准流程

```text
平台运营进入租户管理
        ↓
新建租户申请
        ↓
选择租户类型：药厂 / 服务提供商
        ↓
录入企业主体资料和首位管理员信息
        ↓
保存草稿 / 提交核验
        ↓
主体核验：通过 / 驳回补正
        ↓
审核通过（一个原子业务动作）
        ├─ 创建内部 enterpriseId
        ├─ 生成全局唯一主企业码
        ├─ 创建首位管理员待激活成员关系
        ├─ 创建默认组织和基础角色
        └─ 写入审计日志
        ↓
租户状态：待管理员激活
        ↓
管理员以“企业码 + 手机号 + 验证码”首次登录
        ↓
管理员确认企业信息并完成激活
        ↓
租户状态：正常
```

### 4.2 药厂与服务商分配规则

药厂和服务商的编码生成规则完全相同：

```text
租户审核通过
→ 系统读取租户类型
→ 创建对应类型的企业根节点
→ 生成随机主企业码
→ 将 enterpriseId、enterpriseType、primaryCode 建立唯一绑定
```

类型只影响后续页面、默认角色、资质字段和业务权限：

- 药厂：默认创建药厂管理员相关角色，后续拥有服务商准入审核、品种授权、人员备案等能力。
- 服务商：默认创建服务商管理员相关角色，后续拥有工作组和服务专员管理、发起药厂准入申请等能力。
- 企业码本身不得带 `PHARMA`、`PROVIDER`、企业简称或地区等可推断业务含义。

### 4.3 驳回和补正

1. 审核驳回必须选择标准原因并可填写补充说明。
2. 驳回后不得创建正式租户、企业码或正式管理员账号。
3. 申请人补正后生成新的提交版本，历史资料和审核意见保留。
4. 重新审核通过时只生成一次租户和主码，不得重复创建。

## 五、页面与导航整改

### 5.1 新增导航

在平台侧“系统管理”下新增：

- 一级菜单：`租户管理`
- 页面 ID 建议：`tenant-management`
- 仅平台运营、获授权的系统管理员和超级管理员可见。
- 药厂、服务商、工作组长和服务专员不得看到该菜单，也不得通过直接设置页面状态访问。

### 5.2 租户列表页

必须包含：

- 页面标题“租户管理”和简短说明。
- 主操作“新建租户”。
- 统计概览：待审核、待激活、正常、已暂停；卡片可点击筛选。
- 搜索：企业名称、统一社会信用代码、主企业码；输入做防抖。
- 筛选：租户类型、申请状态、租户状态、创建时间。
- 表格列：企业名称、类型、统一社会信用代码、主企业码、首位管理员、租户状态、申请状态、创建时间、操作。
- 主企业码默认完整展示给平台运营；复制操作必须留下审计记录。
- 空态必须区分“尚无租户”和“筛选无结果”。
- 加载态使用骨架或明确加载提示，不得显示空白页面。
- 请求失败提供错误说明和“重新加载”。
- 长企业名称单行省略，悬停或聚焦后可以查看全称。
- 表格在窄屏下不得强行压扁；使用横向滚动或转为卡片列表。

### 5.3 新建租户向导

采用四步向导：

1. 选择企业类型。
2. 填写企业主体资料。
3. 指定首位管理员。
4. 确认并提交。

通用主体字段：

- 企业法定名称，必填。
- 企业简称，必填，用于界面展示，不参与编码生成。
- 统一社会信用代码，必填，18 位格式校验并全局查重。
- 企业注册地址，必填。
- 企业联系人姓名、手机号，必填。
- 营业执照或证明材料，原型使用模拟附件。
- 备注，选填。

药厂扩展字段：

- 主体分类。
- 药品上市许可持有人/生产企业标识。
- 相关许可证编号和有效期，按原型需要模拟。
- 合规联系人。

服务商扩展字段：

- 服务类型或经营范围。
- 业务负责人。
- 合规负责人。
- 相关资质编号和有效期，按原型需要模拟。

首位管理员字段：

- 姓名、手机号、所属部门、管理员角色。
- 手机号只代表联系方式控制权，不作为租户主键。
- 提交前检查该手机号在本企业是否已有待激活成员；重复提交不得创建两条成员关系。

向导要求：

- 顶部显示步骤和当前进度。
- 返回上一步保留已填数据。
- 关闭未保存向导时提示是否放弃草稿。
- 提交期间按钮显示忙碌状态并禁用重复提交。
- 提交失败保留表单内容。
- 所有必填错误定位到字段，并使用 `aria-describedby`、`aria-invalid`。

### 5.4 审核详情页/抽屉

至少包含以下分区：

- 基本资料。
- 资质材料。
- 首位管理员。
- 提交和审核历史。
- 风险与重复主体提示。
- 审核操作区：通过、驳回、返回列表。

审核通过前显示确认弹窗，明确告知：

> 审核通过后将创建正式租户、生成主企业码并创建待激活管理员。主企业码生成后不可修改。

审核成功反馈：

- 显示企业名称、租户类型、主企业码、管理员手机号脱敏值和当前状态。
- 提供“复制企业码”“查看租户详情”“返回列表”。
- 不提供重新生成主码按钮。

### 5.5 租户详情页

页头显示企业名称、类型、状态和主企业码，内容使用标签页：

1. 基本信息。
2. 企业码管理。
3. 管理员与成员摘要。
4. 状态与生命周期。
5. 操作日志。

主操作根据状态显示：

- 待激活：重发激活提醒、变更首位管理员。
- 正常：暂停租户、申请别名、查看成员。
- 已暂停：恢复租户、终止租户。
- 已终止：只读查看，不允许恢复和新增别名。

## 六、企业码模型与交互

### 6.1 主码规则

- 固定 8 位大写字母和数字。
- 排除 `0/O`、`1/I` 等易混字符。
- 无业务语义，不包含企业简称或类型。
- 全局唯一且忽略大小写。
- 后端生产实现必须使用数据库唯一约束；原型用 mock 集合模拟冲突重试。
- 生成必须与租户创建使用同一幂等业务事务语义。
- 主码生成后不可修改、删除或转移。
- 企业终止后主码永久保留，不得重新分配。

### 6.2 企业码状态

```text
active → suspended → active
active/suspended → retired
```

- `active`：允许定位企业并进入短信验证。
- `suspended`：登录统一提示“企业编码不存在或已停用，请核对后重试”，不得暴露暂停原因。
- `retired`：只保留历史审计，不再允许登录，也不得重新启用给其他企业。

### 6.3 别名码

- 一个租户只能有一个主码，可以有多个别名码。
- 别名和主码共用全局唯一命名空间。
- 别名只能解析到所属主租户，不能形成新的租户或权限边界。
- 别名支持启用、暂停、注销；停用别名不影响主码。
- 别名创建、复制、停用和恢复均写审计。
- 原型至少演示一个有效别名、一个已停用别名及相应登录结果。
- 别名管理不能修改现有主码。

### 6.4 并发与异常

- 审核通过按钮使用 requestId/idempotencyKey，连续点击只创建一个租户。
- 生成码发生冲突时自动重试，不把冲突码展示给用户。
- 如果管理员待激活记录创建失败，整个创建动作显示失败，不留下“有租户但无管理员”的半成品状态。
- 页面刷新后再次打开同一已通过申请，显示已有租户和主码，不重复生成。
- 复制企业码失败时使用普通错误提示，不改变数据状态。

## 七、租户状态与登录联动

### 7.1 租户状态机

```text
draft
→ pending_verification
→ rejected → pending_verification
→ pending_activation
→ active
→ suspended → active
→ terminated
```

### 7.2 状态规则

| 状态 | 是否有正式企业码 | 是否允许管理员激活 | 是否允许日常登录 | 页面表现 |
| --- | --- | --- | --- | --- |
| 草稿 | 否 | 否 | 否 | 可编辑、可删除草稿 |
| 待审核 | 否 | 否 | 否 | 只读等待审核 |
| 已驳回 | 否 | 否 | 否 | 展示原因、允许补正 |
| 待激活 | 是 | 是 | 仅允许首位管理员完成激活 | 显示激活状态 |
| 正常 | 是 | 已完成 | 是 | 正常使用 |
| 已暂停 | 保留 | 否 | 禁止新登录 | 显示暂停原因和恢复入口 |
| 已终止 | 永久保留 | 否 | 否 | 全部只读 |

暂停租户时：

1. 需要填写标准原因和说明。
2. 弹窗明确影响范围：禁止新登录；已有会话按原型规则立即失效或下次请求失效，但必须选定一种并统一演示。
3. 不删除成员、角色、合作、品种授权、备案和审计数据。
4. 恢复后重新按成员、角色和业务授权当前状态计算权限，不自动恢复已经单独过期或被撤销的授权。

## 八、首位管理员激活闭环

1. 审核通过时创建 `pending_activation` 成员关系，但不创建默认密码。
2. 平台向管理员交付企业码，原型用成功结果页和模拟通知记录表示。
3. 管理员输入企业码、手机号，获取并校验验证码。
4. 待激活状态只在验证码成功后披露。
5. 首次登录成功后将成员状态改为正常，并提示“账号已激活，欢迎加入”。
6. 激活成功同步将租户从“待激活”改为“正常”。
7. 同一运行周期再次登录不重复提示激活。
8. 更换首位管理员时，旧邀请失效，新管理员得到新的待激活关系，全过程写审计。
9. 管理员手机号被冻结、停用或已不具备有效角色时，不得错误地把租户激活。

## 九、审计事件清单

| 事件 | 原因码 |

| 生成冲突并重试 | `ENT_CODE_COLLISION_RETRIED` |
| 别名生成 | `ENT_CODE_ALIAS_CREATED` |

## 十一、视觉与响应式整改

### 11.1 字体

- 中文界面优先使用现有系统字体栈，不额外引入网络字体。
- 页面主标题建议 24–28px、字重 600–700、行高 1.25–1.35。
- 卡片标题建议 16–18px、字重 600。
- 正文以 14px 为主，行高 1.55–1.7。
- 辅助文字建议 12–13px；重要业务信息不得使用 10px 或 11px。
- 表单标签最低 13px；输入内容最低 14px。
- 登录页、角色确认页和药厂门页必须使用全局字号 token，不能继续散落硬编码字号。
- 浏览器字号放大到 200% 时，主要任务仍应可完成，不得依赖文字被裁切维持布局。

### 11.2 字间距

- 中文标题、按钮、标签默认 `letter-spacing: 0`，移除负字间距。
- 企业码可使用 `0.04em–0.08em` 的正字间距以提升辨识度。
- 英文大写辅助标题最多使用 `0.04em`，避免过度稀疏。
- 同一组件不得让中文名称继承企业码的字间距。

### 11.3 间距和尺寸

- 使用 4px 或 8px 基础间距体系，禁止出现大量无规律的 7px、13px、19px。
- 页面水平内边距：桌面 24–32px，平板 20–24px，手机 16px。
- 卡片内边距：桌面 24px，手机 16–20px。
- 表单字段垂直间距 16–20px。
- 主按钮、输入框桌面高度 44–48px；触摸端点击区域不小于 44×44px。
- 弹窗正文到操作区至少留 24px。
- 同一行按钮高度、圆角、字体和图标尺寸保持一致。

### 11.4 响应式

登录和认证门页：

- 320px 宽度下不得出现水平裁切。
- 登录输入框和“验证企业”按钮在空间不足时纵向排列。
- 角色卡片和药厂卡片使用单列布局。
- 长企业名称允许换行，企业码保持整体可读。
- 固定底部按钮不得遮挡最后一个表单字段。

业务后台：

- 大于等于 1200px：完整侧边栏和桌面表格。
- 768–1199px：侧边栏默认收起或使用图标模式。
- 小于 768px：侧边栏改抽屉，主内容占满；复杂表格允许横向滚动或改卡片。
- 如果某业务后台明确不支持手机端，必须设置合理最小宽度并显示“请使用更大屏幕访问”，不得让内容静默裁切。
- 禁止仅用 `overflow-x: hidden` 掩盖布局溢出。

### 11.5 颜色和状态

- 正文、辅助文字、占位符、禁用文字分别使用稳定的语义颜色层级。
- 辅助文字不能仅靠低透明度实现层级；需实际测量对比度。
- 普通文本目标对比度不低于 4.5:1，大号文本不低于 3:1。
- 错误、警告、成功状态不能只靠颜色区分，应同时有文字或图标。
- 焦点环必须清晰，不能被圆角卡片或 `overflow` 截断。

### 11.6 表格、抽屉和弹窗

- 表头和数据左对齐规则一致，数字和日期按现有设计统一。
- 操作列固定在右侧时要确保窄屏可访问。
- 危险操作使用二次确认；主操作与危险操作不能使用相同视觉权重。
- 抽屉打开后焦点进入标题或第一个可操作控件，关闭后回到触发按钮。
- 弹窗支持 Esc 关闭，但提交中或不可撤销操作需阻止误关闭并给出说明。

## 十四、必须覆盖的验收场景

### A. 平台创建药厂

- [ ] 平台运营可以从租户列表新建药厂。
- [ ] 主体资料字段和药厂扩展字段完整。
- [ ] 重复统一社会信用代码被阻止。
- [ ] 审核通过后只创建一个药厂租户。
- [ ] 系统生成唯一主企业码，不能手工修改。
- [ ] 首位管理员状态为待激活。
- [ ] 新药厂出现在租户列表和详情页。
- [ ] 新企业码可以进入对应企业的短信验证步骤。
- [ ] 首位管理员首次验证码登录后，管理员和租户均变为正常。

### B. 平台创建服务商

- [ ] 平台运营可以从同一入口新建服务商。
- [ ] 页面展示服务商扩展字段而不是药厂字段。
- [ ] 审核通过后创建服务商企业根和服务商默认管理员角色。
- [ ] 系统生成同一编号空间内的唯一企业码。
- [ ] 使用该码登录后进入服务商工作台，不得进入药厂工作台。
- [ ] 创建服务商不会自动建立任何药厂合作关系。
- [ ] 服务商仍需发起准入申请，药厂审核通过后才建立合作。

### C. 驳回、补正与幂等

- [ ] 驳回不会生成企业码。
- [ ] 驳回原因和历史版本可查看。
- [ ] 补正后可以重新提交。

### D. 企业码管理

- [ ] 主码不可编辑、不可删除、不可重新生成。

- [ ] 暂停租户后主码和所有别名均不能用于新登录。

- [ ] 终止租户后编码永久失效且不能分配给其他租户。

### E. 权限隔离

- [ ] 平台运营可查看并管理租户。
- [ ] 药厂和服务商角色看不到租户管理菜单。
- [ ] 通过直接页面跳转也不能访问未授权页面。
- [ ] 新租户默认没有其他租户的数据权限。

### F. 视觉与交互

- [ ] 1440px、1280px、1024px、768px、390px、320px 分别截图验收。
- [ ] 登录、角色确认、服务药厂门页在 320px 下无裁切。

- [ ] 中文标题无负字间距，企业码字距清晰。

## 十六、完成定义

只有同时满足以下条件，才可以宣称“完整流程已经完成”：

1. 平台运营可以在 UI 中创建药厂和服务商申请。
2. 主体审核通过后系统自动创建租户并生成唯一主企业码。
3. 首位管理员可以用新企业码完成首次登录和激活。
4. 激活后租户正常可用，药厂与服务商进入各自工作台。
5. 主码、别名、租户暂停/恢复/终止均有完整状态和审计闭环。
6. 不同租户之间没有身份、角色、数据或短信票据串用。
7. 登录和关键管理页面在指定桌面及窄屏尺寸下无内容裁切。
8. 字体、字距、间距、对比度、焦点和状态反馈达到本清单要求。
9. 构建通过且没有新增类型错误。
10. 第十四章验收清单逐项有实际验证证据。

在此之前，只能描述为“企业码登录链路已完成”，不得描述为“多租户注册、分配、授权和登录全流程已完成”。
