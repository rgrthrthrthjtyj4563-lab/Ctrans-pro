# 多租户权限、授权与登录 · 未解决问题清单

> 用途：作为下一轮纯前端演示原型整改的唯一问题清单。  
> 范围：只改页面、路由、本地模拟数据和交互状态；不新增后端、接口、数据库或真实鉴权。  
> 优先级：P0 必须整改后才可验收；P1 本轮应整改；P2 体验与交付质量整改。

---

## 一、已拍板口径（不得回归）

1. 平台只有一个平台级身份：`平台系统管理员`。平台不再保留“平台运营”“平台账户管理员”“平台账号与角色”菜单或角色选择。
2. 药厂、服务商均为独立租户；各自管理员只能管理本企业的组织、成员、角色、功能权限和数据范围。
3. 药厂侧身份展示统一为：`企业管理员 · XX部门`；部门不是角色。
4. 工作组既是服务商组织节点，也保留独立“工作组管理”菜单：组织架构管节点和成员，工作组管理管组长与任务承接。
5. 每个有效工作组必须有一名有效组长；组长必须是该组成员、账号启用且持有生效“工作组组长”角色。无有效组长时禁止向该组下派新管理任务。
6. 登录统一采用：`企业编码 + 手机号 + 验证码`。单一可进入药厂自动进入；多药厂才展示选择页；一次会话只能操作一家药厂数据。
7. 服务专员备案异常只拦截学术拜访，不拦截登录或进入药厂业务空间。
8. 业务授权链路固定为：`药厂 → 服务商合作关系 → 产品/品种授权`。服务商内部人员权限只能在药厂授予服务商的有效范围内收窄，不能扩大。
9. 区域不由服务商再次勾选；区域从药厂对产品的授权中派生并只读展示。

## 二、P0：必须整改后才能验收

### P0-00 角色确认页字体错行、内容溢出

**现状问题**

- 角色确认页的表头与角色卡片没有使用同一组列宽和布局规则。
- “数据范围”“功能摘要”“授权状态”等列文字发生错行、重叠或越出卡片边界；授权状态标签漂移到卡片外。
- 该问题直接影响登录主链路展示，当前页面不可作为演示验收页面。

**整改要求**

1. 表头与角色选项行必须复用同一组 CSS Grid 列定义，禁止分别手写宽度。
2. 角色选项行内容使用明确的列容器；长文本允许在本列内换行，不能覆盖相邻列或超出卡片。
3. “角色身份、所属部门/工作组、数据范围、功能摘要、授权状态”在桌面端保持对齐；窄屏改为卡片字段纵向展示，不强行保留五列表格。
4. 授权状态标签与选中标记必须固定在本行可视范围内；不得与文本重叠。
5. 统一行高、字号和字间距，辅助文字不小于 `12px`。

**验收**

- 以 1366px 桌面宽度和 375px 窄屏分别检查：表头与内容逐列对齐，无重叠、截断、漂移或横向溢出。
- 至少验证“企业管理员 · 销售部”这一长身份场景，数据范围、功能摘要、授权状态均可完整辨识。

### P0-01 指定范围没有按已拍板方式实现

**现状问题**

- “指定范围”同时包含内部组织选择、药厂、服务商、品种、区域等概念。
- 当前角色详情中可配置药厂/品种；“已授权成员”页又能按人配置药厂/品种。
- 两处配置并非同一事实源：实际会话主要读取成员授权，角色页的业务范围可能不生效。

**整改要求**

1. 将“组织数据范围”与“业务范围”明确分开呈现，不能混在一个“指定范围”控件中。
2. 服务商的业务范围固定展示为：`药厂 → 当前服务商（只读）→ 已授权品种`。
3. 区域只能作为品种授权的派生信息只读展示，不得成为可选项。
4. 药厂/品种范围只能有一个可编辑事实源。建议采用：**角色配置业务范围，成员页只负责授予/回收角色及生效期**。
5. 删除“同一个角色可以给不同员工配不同药厂/品种范围”的说明、交互和本地数据逻辑；如需人员差异，应建立不同角色。

**验收**

- 服务商管理员无法在两个页面重复维护同一员工的药厂/品种范围。
- 角色配置后，登录门页和全部业务页面读取同一份范围结果。

### P0-02 服务商业务页没有统一按当前服务药厂隔离

**现状问题**

- 任务、结算已部分按当前服务药厂过滤。
- 拜访、服务专员绩效、工作组绩效只按服务商和品种过滤，未按当前服务药厂过滤。
- 预算分析未接入当前登录身份、服务药厂和业务范围。
- 业务明细导出页面文案声称已过滤，实际列表、草稿和导出向导没有读取当前药厂与授权范围。

**整改要求**

1. 所有服务商业务页统一使用同一口径：`当前服务商 + 当前服务药厂 + 已授权产品/品种 + 产品派生区域`。
2. 不允许任何页面自行拼接不完整的过滤条件。
3. 导出列表、详情、草稿、统计卡、筛选下拉和导出结果必须使用同一过滤结果，不能只改提示文案。

**验收**

- 切换服务药厂后，任务、结算、拜访、绩效、预算、导出页面的数据和筛选项同时刷新。
- 同一服务商在两个药厂服务同名产品时，切换药厂后不得串数据。

### P0-03 授权失效后未形成“默认拒绝”

**现状问题**

- 合作暂停、产品授权撤销或成员角色范围失效后，当前会话可能得到空业务范围。
- 多个页面仅在业务范围存在时才筛选；范围为空时，存在展示未过滤数据的风险。

**整改要求**

1. 服务商会话没有有效业务范围时，所有业务页必须默认展示无权限状态，不得展示任何业务数据。
2. 显示统一提示：当前合作、产品授权或角色范围已失效，请重新选择服务药厂或联系管理员。
3. 合作暂停、合作终止、产品授权撤销必须即时影响当前已登录会话，不只影响下一次登录门页。

**验收**

- 在已进入药厂后撤销产品授权或暂停合作，刷新任一业务页均不再展示对应业务数据或操作按钮。

### P0-04 单药厂没有自动进入

**现状问题**

- 当前仅展示“单药厂确认进入”页面，仍需用户点击确认。

**整改要求**

- 当服务商用户名下总记录仅一条且该药厂可进入时，完成角色确认后自动进入该药厂工作台，并提示“正在进入{药厂名}…”。
- 若只有一条记录但不可进入，展示不可进入原因页，不自动进入。

### P0-05 合作关系与业务授权存在职责重叠风险

**最终口径**

- 不合并菜单，保留“合作关系”和“业务授权（产品与区域）”。
- 合作关系只维护：生效、暂停、恢复、终止及原因；不允许配置产品或区域。
- 业务授权是产品和区域的唯一维护入口；只有合作关系生效时可新增、修改或撤销授权。
- 合作关系列表只读展示“已授权产品数 / 授权区域数 / 查看授权”，并跳转业务授权页，不得出现第二个编辑入口。

## 三、P1：本轮应整改

### P1-01 业务授权的字段需要独立拆开

**问题**

当前“服务商品种授权”将授权信息混在一条描述或一个字段中，不利于查看、筛选和编辑。

**整改要求**

在“业务授权（产品与区域）”表单和列表中，至少独立以下字段：

| 字段 | 说明 |
| --- | --- |
| 服务提供方 | 被授权的服务商企业 |
| 药品上市许可持有人 | 药厂/持有人主体 |
| 授权内容 | 本次授权的业务内容 |
| 品种名称 | 被授权产品/品种 |
| 授权区域 | 被授权覆盖区域 |
| 授权状态 | 生效、撤销、已失效等 |
| 生效期 | 生效日期及失效日期 |

列表、搜索筛选和编辑表单均应按上述字段独立呈现；不得把“品种 + 区域”拼成不可拆分的文字。

### P1-02 自定义角色没有租户隔离

**现状问题**

新建角色只按平台域/租户域判断重名，未绑定创建它的具体租户；服务商 A 的自定义角色可能被服务商 B 看见或使用。

**整改要求**

- 自定义租户角色必须带所属 `tenantId`。
- 角色列表、角色授予、权限计算、编辑和删除均按当前租户过滤。
- 预置角色可按租户类型复用，自定义角色不可跨租户可见。

### P1-03 取消药厂后残留品种的逻辑错误

**现状问题**

在角色配置、成员授予、成员编辑中取消某药厂时，品种过滤逻辑方向错误，可能保留已取消药厂的品种。

**整改要求**

- 取消药厂时同步清除仅属于该药厂的已选品种。
- 角色配置、授予成员、编辑成员三处使用同一个处理函数。

### P1-04 品种范围仅用名称，不能严格对应药厂

**现状问题**

不同药厂可能授权同名产品；仅存储品种名称会造成跨药厂串范围。

**整改要求**

- 本地模拟数据以“药厂 ID + 品种 ID（或授权明细 ID）”表示业务范围。
- 页面可展示品种名称，但权限判断不能只依赖品种文字。

### P1-05 工作组三级直达链路需要明确规则

**现状问题**

三级直达链不经过工作组，因而不会触发“无有效组长禁止下派”的规则。

**整改要求**

- 若三级直达保留，流程配置与任务页面明确标注“该链路不经过工作组，不适用工作组组长承接规则”。
- 若业务要求所有管理任务都必须由组长承接，则禁止关闭工作组节点。

### P1-06 旧角色和旧文档口径仍可能误导后续整改

**现状问题**

部分模拟数据、仪表盘文案、旧截图和历史说明仍出现“平台运营”“药厂销售部门”“药厂合规部门”等旧称谓。

**整改要求**

- 当前运行原型不得展示旧平台角色和已删除菜单。
- 历史文件保留可行，但必须标注“历史口径，不作为当前实现依据”；后续执行以本清单为准。

## 四、P2：交互、视觉与交付质量

### P2-01 字号与信息层级

- 辅助文字不得使用小于 `12px` 的字号；当前组织架构、角色管理中仍有 `10px/11px` 文案。
- 角色、组织范围、业务范围、派生区域、成员授权应分区展示，避免让用户误以为它们是一类配置。

### P2-02 窄屏布局

- 角色管理统计卡需具备明确降列策略。
- 表格允许横向滚动，但筛选区、身份信息、弹窗底部操作不能被压缩或遮挡。

### P2-03 验收材料

- 旧截图目录仍有已删除菜单和旧平台角色页面，不得作为本轮验收依据。
- 整改完成后更新以下截图或走查说明：平台登录、服务商单药厂自动进入、多药厂选择与切换、角色与业务范围、工作组无组长拦截、合作关系、业务授权字段列表、授权撤销后的业务页空态。

### P2-04 构建体积

- 当前主 JS 构建产物存在超过 500KB 的告警。该项不阻断原型功能验收，但后续可按页面动态加载优化。

## 五、最终验收清单

- [ ] 平台只保留“平台系统管理员”，不出现平台角色选择、平台运营或平台账号与角色菜单。
- [ ] 角色确认页在桌面端表头与内容列对齐、无字体错行；窄屏使用纵向卡片字段展示。
- [ ] 服务商业务范围只存在一个可编辑事实源；显示层级为“药厂 → 当前服务商（只读）→ 已授权品种”，区域仅派生展示。
- [ ] 当前服务商会话的数据严格按“服务商 + 当前药厂 + 产品/品种 + 派生区域”过滤。
- [ ] 合作暂停、合作终止、产品授权撤销、角色范围失效后，当前会话默认拒绝访问业务数据。
- [ ] 单一可进入药厂自动进入；多药厂才进入选择页。
- [ ] 合作关系不维护产品和区域；业务授权是产品、区域唯一维护入口。
- [ ] 业务授权列表和表单将服务提供方、上市许可持有人、授权内容、品种名称、授权区域、状态、生效期独立展示。
- [ ] 自定义角色仅在所属租户内可见和可授予。
- [ ] 取消药厂后，不残留该药厂的品种授权。
- [ ] 无有效组长的工作组不能接收新的管理任务；三级直达链路规则已明确。
- [ ] 运行页面不展示废弃角色、废弃菜单和旧口径。
- [ ] `npx tsc --noEmit`、`npm run build`、`git diff --check` 均通过。
