# 菜单管理 · 轻量设计方案

> 版本：V1.0（2026-09-03）  
> 适用范围：贝医药合作系统原型 `业务分析与设计准备/`。

## 1. 目标

在“系统管理”中补充一个基础的菜单管理页面，让系统管理员可以维护左侧导航的菜单名称、层级、图标、排序和启停状态。

菜单管理只解决“菜单怎么展示”；角色权限仍决定“谁能访问页面、谁能操作按钮”。两者不合并，避免权限规则分散。

## 2. 范围

### 本期做

- 维护一级目录和二级菜单，最多两层；
- 新增、编辑、上移、下移、启用、停用；
- 菜单绑定已存在的系统页面；
- 左侧导航按菜单配置渲染；
- 仅平台运营、系统管理员可进入菜单管理；
- 菜单变更写入操作日志。

### 本期不做

- 不做多租户单独菜单配置；
- 不做菜单发布版本、草稿、回滚；
- 不做外链、iframe、拖拽排序；
- 不在菜单页配置角色、按钮、字段或数据范围；
- 不允许通过菜单管理创建新页面。

## 3. 菜单位置

```text
系统管理
├─ 角色管理
├─ 菜单管理        ← 新增
├─ 用户与组织
├─ 角色预览
├─ 操作日志
└─ 执行链路配置
```

菜单管理页面对应资源为 `menus`，仅授予以下角色：

| 角色 | 权限 |
| --- | --- |
| 平台运营 | 查看、新增、编辑、启用/停用 |
| 系统管理员 | 查看、新增、编辑、启用/停用 |
| 其他角色 | 无入口、无访问权限 |

## 4. 菜单数据

```ts
export type MenuType = "group" | "page";

export interface MenuItem {
  id: string;
  name: string;
  type: MenuType;             // group=目录，page=页面菜单
  parentId: string | null;    // 页面菜单必须归属一个目录
  pageId?: PageId;            // type=page 时必填，关联已有页面
  icon?: string;              // 一级目录图标
  sort: number;               // 同级排序
  enabled: boolean;
  updatedAt: string;
  updatedBy: string;
}
```

规则：

1. 目录不能绑定页面；页面菜单必须绑定一个已有 `PageId`。
2. 同一目录下菜单名称不能重复；一个页面只能绑定一个启用菜单。
3. 停用目录时，其下菜单一并不显示；恢复目录后，子菜单仍按自己的启停状态判断。
4. 已绑定菜单的页面不能在菜单管理中删除；如不需要展示，直接停用菜单。
5. 菜单排序只允许同级“上移 / 下移”。

## 5. 页面设计

页面采用左侧菜单树、右侧详情的简单布局。

### 左侧菜单树

- 按当前侧栏结构展示目录和菜单；
- 每项显示名称和状态：启用 / 已停用；
- 目录行操作：新增子菜单、编辑、上移、下移、启用/停用；
- 菜单行操作：编辑、上移、下移、启用/停用；
- 顶部提供“新增目录”按钮。

### 右侧编辑表单

| 字段 | 目录 | 页面菜单 |
| --- | --- | --- |
| 菜单名称 | 必填 | 必填 |
| 上级目录 | 无 | 必填 |
| 关联页面 | 无 | 必填，从已有页面列表选择 |
| 图标 | 可选 | 不配置，继承目录视觉 |
| 启用状态 | 可编辑 | 可编辑 |

保存后立即更新左侧导航，不需要发布步骤。

## 6. 与权限的关系

菜单显示使用以下简单规则：

```text
显示页面菜单 = 菜单已启用 AND 当前角色拥有该页面的 view 权限
显示目录     = 目录已启用 AND 至少有一个可显示的子菜单
```

因此：

- 菜单启用不代表所有人都能看到；没有页面查看权限的角色仍看不到该菜单。
- 菜单停用时，所有角色的侧栏都不显示该入口。
- 用户手工输入页面地址时，继续使用现有页面权限校验；菜单管理不能绕过角色权限。

## 7. 原型落地

| 文件 | 调整 |
| --- | --- |
| `src/types.ts` | 增加 `MenuItem`；`PageId` 增加 `menus`。 |
| `src/data/permissions.ts` | `RESOURCE_PAGES` 增加“菜单管理”；为平台运营、系统管理员配置权限。 |
| `src/data/menus.ts`（新增） | 保存当前菜单树种子数据和树形转换函数。 |
| `src/pages/MenuManage.tsx`（新增） | 实现菜单树、编辑弹窗及启停/排序操作。 |
| `src/App.tsx` | 以菜单数据替代硬编码 `navGroups` 渲染侧栏；增加 `menus` 路由。 |

首期可用 React state 保存菜单配置；刷新页面后恢复默认菜单。接真实后端时再把 `MenuItem[]` 换成接口数据即可。

## 8. 验收标准

- [ ] 系统管理下有“菜单管理”，且仅平台运营、系统管理员可见。
- [ ] 可新增一级目录和二级页面菜单；页面菜单只能选择已存在页面。
- [ ] 可修改名称、图标、所属目录，并可同级上移、下移。
- [ ] 停用菜单后，侧栏不显示；启用后恢复显示。
- [ ] 角色没有页面查看权限时，即使菜单已启用也不显示。
- [ ] 停用目录后，其下所有菜单均不显示。
- [ ] 新增、编辑、启用/停用均写入操作日志。
- [ ] `npm run build` 通过，既有页面跳转和权限拦截不受影响。
