# 首页重构 AI 提示词（Dashboard 角色化改造）

> 用途：投喂给 AI 编码工具（Figma Make / Cursor / Claude 等），对 `重构/业务分析与设计准备` 的首页做角色化重构。
> 提示词自包含全部设计要求，不依赖外部文档。设计依据：《角色首页重设计方案 V2》（Obsidian）。

---

## 提示词正文（从此处开始复制）

你是一位资深前端架构师 + B 端产品工程师，负责重构本项目（React 19 + Vite + TypeScript + Tailwind CSS v4 + lucide-react，数据全部来自 `src/data/mockData.ts` 的模拟数据）的首页工作台。

### 背景与问题

当前 `src/pages/Dashboard.tsx` 是一套"通用监控大屏"：组件只接收 `navigate`、不接收角色，App 层的角色切换器（平台运营/药厂管理员/服务提供商/工作组长/服务专员）只改显示文案，KPI 卡、AI 洞察、优先处理队列对五套角色完全相同。这违反了本系统最核心的设计原则：**首页 = 该角色「当天必须知道的事 + 当天必须处理的事」，不同角色的首页必须是不同页面，而不是同一页面换菜单。**

### 总设计原则（必须遵守）

1. **指标准入铁律**：每张 KPI 卡必须能触发一个管理动作；"好看但无用"的总量数据（如"本月累计完成 234 次拜访"）一律不准上首页。
2. **消息即待办**：所有系统提醒（任务四级提醒、预算预警、随检通知、审批待办）必须以首页待办形态呈现且有处理入口。
3. **穿透式下钻**：任何 KPI/队列条目的"处理"按钮要能到达对应业务页面（原型层面允许跳列表页，但队列条目应携带单据语义，不是按 type 粗跳三个页面）。
4. **AI 辅助不裁决**：AI 洞察一律"仅提示不强制"，不自动改单据状态；所有 AI 输出带"人工确认"语义。
5. **优先处理队列排序保持**：逾期 > 风险 > 关注 > 正常，逾期行红色背景（现有实现正确，保留）。

### 任务一：首页角色参数化（最高优先级）

- `Dashboard` 组件签名改为接收当前角色 `role: Role`（从 App 层角色切换器真实传入，切换角色时首页内容必须随之变化，不允许只改文案）。
- 以下所有区块（KPI 行、AI 洞察、优先处理队列、趋势/分布区、快捷入口、消息待办）全部按角色渲染差异化内容，数据从 `mockData.ts` 中为每个角色准备独立 mock。

### 任务二：新增消息/待办中心

- 顶部导航增加消息中心图标（铃铛）带未读角标；首页右栏新增"消息待办"列表区（与"最近操作"并存，最近操作是审计视角、消息待办是行动视角，两者不可合并）。
- 消息按类型分标签：任务提醒（截止前 3 天/1 天/1 小时/超期，四级颜色渐进）、预算预警（未分配至任务包/执行超期）、随检通知、审批待办、转办通知。内容按角色过滤：执行岗收任务提醒，管理岗收审批与预警。

### 任务三：五角色首页逐一实现

**1. 药厂管理员（销售视角）— 核心命题"活干得怎么样、预算超没超"**

- KPI 五张：今日拜访量（大数字+较昨日涨跌）、有效拜访率（百分比+达标线）、任务包执行进度（已完成/总包，落后时间进度标红）、预算执行率（消耗/月度预算，对照时间进度）、超期未填报（人数，红色）。
- 中部：近 7 日拜访趋势折线 + 区域排名（TOP5/垫底5）+ **双队伍执行对比**（自营团队 vs 各服务商：任务完成率/证据链通过率/超期率三列小表格）。
- AI 洞察（销售侧示例）："华南区 3 个任务包进度落后时间进度 15%"（依据+置信度+建议动作：催办）。

**2. 药厂合规管理员（新增角色，加入角色切换器）— 核心命题"有没有出事、要不要处理"**

- KPI 两行八张：今日新增风险、高危风险 P0（红色高亮）、待处理事件、备案异常、异常拜访、**供应商准入待审**、**资质到期预警（30/60/90 天分段）**、**待随检任务**。
- 新增**随检工作台**区块，三栏：待随检推荐（AI 风险加权推荐今日最该查的任务）、随检进行中（摄像头/定位状态）、抽检结果待处理。
- 预警两层 UI 必须用颜色区分：橙=合规告警（监管政策，审批门槛）、蓝=风控提示（系统建议，人工核实）。
- 中部：近 30 日风险趋势 + 按类型/区域分布 + 重点对象（高风险医生/代表）。

**3. 服务提供商 — 核心命题"接了哪些活、下属怎么管、结多少钱"**

- KPI 六张：承接任务数、待分配工作量、在岗服务专员、本月结算金额、待初审数据、超期未填报专员数（红色）。
- 中部：任务/工作量趋势 + 工作组排名。
- 初审视角：待初审队列每条带 AI 预审标签（如"照片清晰度不足""定位漂移"），存疑优先展示。

**4. 工作组长 — 核心命题"待我初审什么、组员负荷如何"**

- KPI：待我初审（含 AI 存疑数）、本组今日任务完成、组员负荷（超载人数）、本组超期未填报。
- 队列：待我初审记录（带 AI 预审标签）优先，其次组员超期任务。

**5. 服务专员 — 核心命题"我今天要干什么"**

- 第一屏改为**今日任务清单**：按截止紧急度排序，每条带四级提醒状态（3 天/1 天/1 小时/已超期，颜色渐进），支持"去填报"直达。
- 小卡片：我的证据链完整度、我的本月结算。
- AI 填报助手提示条：拍照归类证据链、缺项前置提示。
- 注意：专员看不到任何全局统计（拜访分布、待结算总金额等），只能看到本人数据。

（可选第 6 档：平台运营保留现有布局作为全局监控视图，但需加消息中心。）

### 任务四：AI 呈现规范（升级现有 AIInsightCard）

每条 AI 洞察强制包含六要素，缺一不可：**结论 / 依据（命中的规则）/ 数据范围 / 置信度（高/中/低）/ 建议动作按钮 / 人工确认语义**。每条可"忽略"并可标记"有效/误报"。洞察内容按角色不同（每个角色至少 2-3 条贴合其命题的示例数据）。

### 数据与组件要求

- 在 `mockData.ts` 中为每个角色扩展独立的数据结构（角色化 KPI、消息、队列、洞察），保持 TypeScript 类型完整。
- 可新增组件（如 MessageCenter、TaskList、InspectionWorkbench、RoleKpiRow），复用现有 MetricCard / AIInsightCard / StatusTag / Button 风格，视觉令牌遵循项目现有基线（主色 #176B5B、页面背景 #F5F7F8、8px 间距体系）。
- 保持现有文件结构约定（pages/ components/ data/ types），不引入新依赖。

### 验收标准

1. 切换五个角色，首页 KPI 数量与内容、AI 洞察、队列内容、快捷入口全部不同；
2. 合规管理员角色存在且有随检工作台 + 两层橙/蓝预警；
3. 服务专员首页是今日任务清单，无任何全局统计；
4. 消息中心有角标、有分类、每条可跳转；
5. 优先队列排序仍为 逾期>风险>关注>正常；
6. AI 洞察六要素齐全，且页面上保留"AI 仅提供参考，所有操作需人工确认"声明；
7. `pnpm build`（或项目现有构建方式）无 TypeScript 错误。

### 不要做

- 不要改动 Dashboard 之外的现有业务页面（VisitManagement、PromotionTasks 等）的内部逻辑；
- 不要把角色差异做成"同一套数据换标题"——数据本身必须角色化；
- 不要添加"本月累计完成 N 次"类无动作价值的总量指标；
- 不要让 AI 洞察自动改变任何单据状态或队列排序以外的数据。
