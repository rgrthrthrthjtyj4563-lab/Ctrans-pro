# 征求意见纪要｜问卷与价目的绑定关系应放在哪一侧

整理日期：2026-11-09
用途：请另一位 AI/专家独立评估下述架构决策问题。本文自包含全部背景，不依赖其他材料。文末列出希望对方回答的问题清单。

---

## 一、业务背景（自包含）

医药营销协同 SaaS，药厂（甲方）通过服务商向终端（医生/患者/商业公司）开展推广服务。与本问题相关的三个业务对象：

**1. 问卷库（药厂维护）**
- 字段：问卷编码、名称、问卷类型（约 24 种：通用/满意度/合理用药/品牌知名度…）、**填写对象（医生/患者/商业公司，3 值枚举）**、适用品种（**可空=全品种**）、题目版本（每次替换题目生成新版本，**任务下发时锁定版本**）、状态（启用/停用）
- 问卷可跨任务复用；已被任务引用的问卷不能删除只能停用

**2. 价目体系（药厂维护）**
- **价格按品种隔离**：每个品种一本价目表；另有公私两套价格（对公/对私）
- 结构三级：业务大类（如「问卷调查」）→ 价目类别（如「问卷调研」，跨品种存在）→ 档位 → 价格行
- 问卷调查大类的**档位维度已确定为「填写对象」**（医生/患者/商业公司三档，各一个单价）
- 已确认的业务结论：**问卷主题与报价分开**（不按主题预置价格）；**同价的多份问卷共用一条价目**；确有不同报价的问卷分别使用各自的价目

**3. 任务（药厂创建下发）**
- 一个任务可关联**多份问卷**，每份问卷可能单价不同，**分别填计划量、汇总金额**
- 任务下发时**锁定题目版本 + 价格快照**，之后改题/改价不影响已下发任务

**组织事实**：原型中同一药厂账号既建问卷又配价目；正式系统权限按资源隔离（「问卷配置」「价目配置」是两个独立权限资源，可授予不同人）。

---

## 二、待决策问题（精确表述）

> **「哪份问卷按哪条价目计价」这一关联关系，应该由谁持有（数据归属）、在哪一侧配置（操作入口）、如何消歧（一份问卷被多条价目覆盖时按哪条）？**

---

## 三、候选方案

### 方案 A：价目侧持有（价目行维护「适用问卷范围」）
- 数据形态：`价目类别 → { scope: 全部问卷 | 指定问卷清单[] }`
- 问卷对象上**不存任何价格/价目字段**，只读回显「当前适用价目」
- 已用原型实现此方案

### 方案 B：问卷侧持有（每份问卷引用一条价目）
- 数据形态：`问卷 → 价目类别引用（恰好一条）`
- 价目页不知道自己管哪些问卷；问卷新建/编辑时选择计价价目

### 方案 C：A 的存储 + 双侧编辑入口（折中）
- 关系真身仍在价目侧（同 A），但在**新建问卷弹窗增加「计价」步骤**（默认继承「全部问卷」价目，或显式选专属价目），写入同一份绑定；问卷页「适用价目」可编辑
- 歧义规则固定两级：**专属（指定该问卷）> 全部问卷**

---

## 四、两方案对比（力求公允）

| 维度 | A：价目侧持有 | B：问卷侧持有 |
| --- | --- | --- |
| 取价歧义 | 需优先级规则（专属>全部），永久复杂度税 | 每问卷恰好一个引用，**天然无歧义** |
| 漏配风险 | 新问卷默认无价，需「未定价」提醒兜底 | 创建即绑定，不会漏 |
| 职责边界 | 建问卷的人不碰价格心智，权限干净 | 建问卷的人被迫做商务选择（选错=结算错）；需新增「引用价目」类权限 |
| 同价批量 | 「全部问卷」范围下新增问卷零操作 | 同价 N 份 = N 次逐份选择 |
| 换价操作 | 要动价目侧两处（旧范围移出、新范围加入） | 问卷上一处改引用 |
| 引用完整性 | 价目删除=关系自然消失，无悬挂引用 | 价目停用/删除时 N 份问卷悬挂，需级联处理 |
| 计价引擎查询 | 需反查（遍历绑定找覆盖该问卷的价目） | 查询方向与存储方向一致，直接取 |

**补充事实（影响权重）**：该业务中「大多数问卷同价」预计是常态（同对象同价），例外才单独定价——这使 A 的「全部问卷」范围模式可能成为主要用法；但若业务实际是「每份问卷单独议价」，则 B 的逐份引用更贴合。

**一个已排除的方案**：按问卷类型/对象**自动匹配**（无显式绑定）——被否，因会把「主题」重新耦合回「价格」，违背已确认结论；且新增类型必须建价目。

## 五、当前状态与倾向（仅供参考，欢迎推翻）

- 方案 A 已在原型中实现并跑通端到端（含问卷页只读回显「适用价目/未定价」）
- 团队当前倾向：**方案 C**（A 的存储 + 问卷侧补一个「计价」入口），理由是「全部问卷」常态下新增零操作，同时消掉 A 的漏配与换价痛点
- 疑虑：C 是否只是把复杂度藏起来？双侧编辑同一关系是否会带来一致性/权限的新问题？

## 六、希望对方回答的问题

1. 关系（外键）应放价目侧还是问卷侧？**核心判断依据是什么**（请给出可迁移的建模原则，而非仅针对本例）？
2. 「范围式绑定（全部/指定清单）」与「逐份引用」哪个更符合本业务？「大多数同价」这一预期事实应如何影响选择？
3. 若采用方案 C（双侧入口编辑同一关系），有哪些必须防范的一致性/权限陷阱？是否值得？
4. 覆盖歧义的最简规则是否就是「专属 > 全部」两级？有没有更简单的消歧设计？
5. 漏配（问卷无价）在流程上如何兜底最稳：新建时强制、任务侧禁选、还是事后提醒？
6. 从结算/计价引擎的实现成本看，A/B/C 哪个长期更省？
7. **你的最终建议**：A / B / C 三选一，并用三句话说明为什么另外两个不选。
