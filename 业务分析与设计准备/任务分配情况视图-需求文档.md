# 任务“分配情况”视图需求文档

## 1. 背景与目标

现有任务详情能够查看任务金额、服务商和执行状态，但药厂无法在一个视图中连续追踪“药厂 → 服务提供商 → 工作组 → 服务专员”的分配与执行状态。新增“分配情况”页签，帮助药厂快速识别任务是否已拆到工作组、是否已分配到个人、哪些工作量已完成以及绩效处于什么状态。

## 2. 入口与用户

- 入口：任务执行列表 → 打开单个任务详情 → “分配情况”页签。
- 主要用户：药厂销售部门；药厂合规部门只读查看。
- 本期范围：查看分配链路，不提供药厂直接调整工作组或服务专员分配的操作。
- 工作组和服务专员的分配动作沿用既有任务执行链路。

## 3. 页面结构

### 3.1 任务上下文

展示任务编号、任务名称、服务商、品种、任务金额、区域、起止时间、任务状态和对账状态，避免进入页签后丢失任务上下文。

### 3.2 分配链路概览

使用横向链路展示：

`药厂 → 服务提供商 → 工作组 → 服务专员`

节点展示对应名称、工作组数量、服务专员数量及完成进度。

### 3.3 工作组分配表

每个工作组为一个分组行，展示：

| 字段 | 说明 |
| --- | --- |
| 工作组 | 工作组名称 |
| 工作组任务金额 | 分配给工作组的金额 |
| 区域 | 省级区域，沿用任务区域 |
| 分配状态 | 未分配 / 部分分配 / 已分配 |
| 已分配 | 工作量总数 |
| 已完成 | 已完成工作量 |
| 待审核 | 已提交但尚未审核的工作量 |
| 未完成 | 已分配但尚未完成的工作量 |

### 3.4 服务专员明细

工作组下直接展示服务专员，不需要二级点击。每名服务专员展示姓名、分配工作量、已完成、待审核、未完成、完成率和绩效情况。

绩效状态沿用现有状态：未完成、待审核、已通过、已打绩效、已结算、已驳回。完成量不等于绩效状态，已完成但未审核的记录必须显示为“待审核”。

### 3.5 业务项目明细

按医院拜访、商业拜访、药房拜访、会议活动、调研等项目展示计划量、已分配、已完成、待审核和金额。

## 4. 展示规则

- 计划量、已分配、已完成全部为 0 的项目隐藏。
- 只要计划、分配或完成任一字段不为 0，就保留该项目。
- 计划量为 0 但完成量大于 0 的记录必须展示，并标记“异常数据”。
- 工作组或服务专员只要存在有效分配，即使完成量为 0 也保留。
- 没有有效工作组分配时显示“暂未分配到工作组”。
- 金额统一使用人民币全角符号“￥”和千分位格式。
- 工作组状态使用统一标签颜色；绩效状态使用既有状态标签。

## 5. 数据模型与接口约束

按任务编号一次返回完整分配链路，数据至少包含：任务与服务商关系、工作组金额与区域、工作组状态、服务专员分配量与完成量、绩效状态、业务项目明细。

原型 mock 数据需覆盖多工作组、一个工作组多人、未分配、部分分配、已分配、已通过、待审核、已打绩效、全零项目隐藏及异常完成数据。

## 6. 权限

- 药厂销售部门：查看完整分配情况。
- 药厂合规部门：只读查看。
- 服务商及其他角色：沿用现有任务详情权限，不因本页新增管理操作。

## 7. 异常与空状态

- 无工作组：显示“暂未分配到工作组”及说明。
- 工作组无专员：显示“暂未分配到服务专员”。
- 完成量大于计划量：展示异常图标和“异常数据”提示。
- 后端字段缺失：展示“—”，不得将缺失值默认为 0。

## 8. 原型验收标准

1. 任务详情存在“分配情况”页签。
2. 页面能展示药厂到服务专员的完整链路。
3. 工作组金额、区域、分配状态和个人绩效状态正确。
4. 不需要二次点击即可看到服务专员明细。
5. 全零项目隐藏，异常完成数据保留并提示。
6. 无分配任务显示空状态。
7. 其他任务详情页签和任务列表功能不受影响。
8. 1280px 宽度下表格可横向滚动，主要信息可读。

## 9. 待后端确认

- 工作量的统一计量单位是否按次数、场次等业务项目分别统计。
- “已完成”“待审核”“未完成”是否由后端直接汇总，还是前端按明细计算。
- 绩效状态与审核状态的最终联动规则。
- 异常数据是否需要提供处理入口和审计记录。
