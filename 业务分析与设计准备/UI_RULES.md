# UI 实施规则

> 适用范围：`业务分析与设计准备` 的纯前端演示。  
> 规范关系：本文件规定可执行的 UI 使用方式；`../UI设计基线与首批页面说明.md` 规定业务状态、页面模板与设计原则。出现冲突时，以后者的业务语义为准。

## 使用原则

1. 新页面先复用 `src/components` 中已有组件；不复制按钮、弹窗、状态标签、分页或筛选栏的实现。
2. 颜色、间距、圆角、阴影与字号优先使用 `src/index.css` 中的 token；禁止在页面里重新定义品牌色、状态色和按钮尺寸。
3. 颜色不能是唯一的信息载体。状态必须有文字，危险操作必须有明确文案和确认弹窗。
4. 本项目是演示原型：不以假的成功提示掩盖未实现的真实写入、上传、付款或审批能力。

## 字体与排版

| 场景 | 规则 |
| --- | --- |
| 界面正文 | 使用 `var(--font-sans)`；默认 14px，行高 1.5715。 |
| 表格与辅助文字 | 13px / 12px；不得小于 12px。 |
| 页面标题 | 20px、600 字重；区块标题使用 16px、600 字重。 |
| 金额、编号、日期时间 | 使用 `.font-mono-nums`，保证数字等宽。 |
| 字体来源 | 使用已定义字体栈；新增字体前必须说明离线可用性与演示稳定性。 |

## 图标

- 唯一图标库为 `lucide-react`，使用线性图标；不引入 emoji、Unicode 图标或第二套图标库。
- 常规尺寸：表格操作 14px，按钮/表单 14–16px，导航 18px，空状态 32–40px。
- 图标与文字并列时，图标只辅助动作语义；删除、冻结、撤销、驳回等风险动作必须保留文字。
- 纯图标按钮必须使用 `IconButton`，且必须提供 `title` 和 `aria-label`。装饰性图标写 `aria-hidden`。

## 按钮与操作层级

| 组件 / 变体 | 用途 | 页面限制 |
| --- | --- | --- |
| `Button primary` | 新建、查询、提交、保存等主动作 | 同一操作区域通常只保留一个。 |
| `Button secondary` / `outline` | 次要动作、取消、返回 | 不得与主动作争夺视觉重点。 |
| `Button ghost` | 表格行内低风险动作 | 危险操作应置于“更多”或确认流程中。 |
| `Button danger` | 确认删除、冻结、驳回等破坏性动作 | 必须先展示影响说明。 |
| `IconButton` | 紧凑且语义明确的单动作 | 不能作为危险操作的唯一入口。 |

按钮尺寸固定为 `sm` 28px、`md` 32px、`lg` 38px。业务页面不得自行写按钮高度、圆角、品牌色或 hover 色。

## 表单、表格与反馈

- 表单标签位于控件上方，必填项以文字或 `*` 明示；错误信息靠近字段并说明修正方式。
- 列表页保持“页头 → 筛选 → 摘要（按需）→ 表格 → 分页”的结构；默认筛选不超过 6 项。
- 表格操作顺序固定为“查看 → 编辑 → 主要动作 → 更多”；表格内危险操作不直接执行。
- 空状态必须说明原因和下一步。加载、成功、失败均需要可见反馈；不可逆动作使用 `ConfirmDialog`。

## 无障碍与自检

- `:focus-visible` 始终可见；不要为了视觉效果移除焦点框。
- 禁用控件保持可辨识的禁用态，不能只靠 `cursor` 表示。
- 新增过渡时间应不超过 200ms，并尊重 `prefers-reduced-motion`。
- 提交前检查：是否复用通用组件和 token、主操作是否唯一、危险操作是否确认、图标按钮是否有文字替代、1440px 下是否无页面横向溢出。
