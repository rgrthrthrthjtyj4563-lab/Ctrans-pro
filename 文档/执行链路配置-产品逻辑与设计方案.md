## 1. 背景与目标

当前系统的任务执行链固定为四级：**药厂 → 服务提供商 → 工作组 → 服务专员**，层级写死在类型、数据与页面中。真实业务里存在不需要工作组层的服务商（小团队直管代表），需要允许药厂按自身情况删减「工作组」这一层。

本方案交付一套**执行链路配置机制**：

- 药厂管理员在「系统管理 → 执行链路配置」中，可将执行链在四级链与三级链之间切换；
- 任务、拆包、任务详情、服务商品种授权等触点随链路形态联动；
- 存量任务不受配置影响，按创建时锁定的链路执行完毕。

一句话产品定义：

> **执行链路配置决定「工作量从服务商往下怎么走」：经工作组转一手，还是服务商直发专员。**

## 2. 决策记录（已拍板，不再议）

| # | 决策 | 落地口径 |
|---|---|---|
| D1 | 仅「工作组」层可删减 | 支持四级链 / 三级链两种形态；数据建模为节点数组，未来可扩展但本期 UI 只开放工作组开关 |

| D3 | 仅新任务生效 | 任务创建时写入链路快照，快照不可变（同 `priceBookSnapshot` 模式）；存量任务按原链执行 |
| D4 | 配置页 + 链路图示 | 不做拖拽式流程编辑器；页面视觉以已确认的预览页为准 |

| D6 | 服务商品种授权联动 | 三级链下，服务商的品种授权对象从「工作组」变为「服务专员」（详见第 4 节） |

## 3. 产品逻辑

### 3.1 链路两态模型

链路状态只有两态，禁止发明第三态：

```text
工作组启用（四级链）：药厂 → 服务提供商 → 工作组 → 服务专员
工作组停用（三级链）：药厂 → 服务提供商 → ────────→ 服务专员
```

- 开关语义：开关只挂在「工作组」节点上，其余三层固定不可停用；
- 停用工作组 = 新建任务不再有「拆解到工作组」环节，服务商把工作量直接分配给服务专员；
- 重新启用 = 新建任务恢复四级链。

### 3.2 配置生效规则

| 规则 | 说明 |
|---|---|
| 全局生效 | 药厂维度一条链，全系统任务共用；不按服务商、不按任务单独配置 |
| 仅新任务生效 | 任务创建时把当前链快照进 `Task.chainSnapshot`；此后配置无论如何变化，不回写任何存量任务 |
| 快照不可变 | 与 `priceBookSnapshot` 同一铁律；页面上不存在编辑存量任务链路的入口 |
| 变更留痕 | 每次启停写一条变更记录（时间、操作人、动作、影响说明），倒序展示；操作只影响「调整后新建的任务」 |
| 停用需确认 | 停用走确认弹窗（三点影响说明，危险色按钮「停用工作组」）；启用直接生效 + 轻提示 |

### 3.3 影响范围矩阵（触点 × 两态差异）

| 触点 | 四级链（工作组启用） | 三级链（工作组停用） |
|---|---|---|
| 执行链路配置页（系统管理） | 四节点全生效 | 工作组节点停用态（虚线、降透明、「已停用」标签） |
| 任务执行 · 拆分任务包（服务商） | 标题「拆分任务包」，按**工作组**分配次数；人力测算按组人数 | 标题「分配任务量给服务专员」，按**服务专员**分配；人力测算按所选专员数 × 单人日基准 |
| 任务执行 · 列表「分配阶段」列 | 未拆解 → 已拆解到工作组 → 已分配到专员 | 未拆解 → 已分配到专员（跳过「已拆解到工作组」档） |
| 任务详情 · meta 区 | 执行链：四级链 | 执行链：三级链 |
| 任务详情 · 任务拆解页签 | 按工作组聚合 → 展开专员明细 | 直接按专员聚合（无工作组层级） |
| 品种授权 · 服务商授权页签 | 授权对象 = **工作组** | 授权对象 = **服务专员** |
| 品种授权 · 拆包可选对象（D7） | 工作组下拉按「服务商→工作组」授权过滤 | 专员下拉按「服务商→专员」授权过滤 |

### 3.4 明确不受影响的环节

| 环节 | 不变原因 |
|---|---|
| 新建任务弹窗 | 任务由药厂发给服务商，链路差异发生在服务商确认之后；创建流程与字段完全一致，不加说明行（D9①） |
| 任务五步流转 | 发包 → 确认 → 执行分配 → 执行完成 → 结算的业务顺序不变；当前系统无步骤条组件，本方案不新增（D9②） |
| 发起结算 | 一直以来都按「服务月份 + 服务专员」勾选已审核任务量，不随链路变化（D9④） |
| 绩效、备案、服务商准入 | 与工作组层无数据耦合，维持现状 |
| 登录角色体系 | 不新增登录角色，不修改 `Role` / `BizRole` / 权限矩阵既有语义 |

## 4. 服务商品种授权设计（本方案核心新增）

### 4.1 现状与问题

- 现有「品种授权」页只有一层：**药厂 → 服务商**（`VarietyProviderAuth`，同一品种同一区域仅一家服务商）；
- 真实系统存在三层品种授权（服务商→工作组、工作组→专员），本期原型未实现，拆包时也不做品种过滤；
- 引入三级链后，「服务商授权给谁」必须跟随链路：四级链授权给工作组，三级链直接授权给服务专员——这是本机制的新增联动点（D6）。

### 4.2 授权模型

新增「服务商下层授权」实体，与现有 `VarietyProviderAuth` 并列：

```ts
export type SubAuthTargetType = '工作组' | '服务专员';

export interface ProviderSubAuth {
  id: string;
  provider: string;          // 授权方（服务提供商），演示环境固定为智联科技有限公司
  targetType: SubAuthTargetType;
  targetName: string;        // 工作组名（工作组一…）或 服务专员姓名
  varietyId: string;
  varietyName: string;
  regions: string[];         // 省级或「全国」，与现有授权同口径
  createdAt: string;
  createdBy: string;
}
```

约束规则：

- 唯一性：同一 `provider + targetType + targetName + variety + 区域` 仅一条（复用 `assertAuthUnique` 的校验模式）；
- 对象类型：新增授权的 `targetType` 必须等于**当前生效链路**的下一层（四级链=工作组，三级链=服务专员）；
- 区域粒度：省级或全国，不做市/区县（与备案域 P2 遗留一致）。

### 4.3 页面设计：品种授权页双页签（D8）

现有「主数据管理 → 品种授权」页改造为双页签：

| 页签 | 内容 | 可写角色 | 只读角色 |
|---|---|---|---|
| 药厂授权（现状） | 药厂 → 服务商 的品种×区域授权，功能不变 | 药厂销售部门 | 服务提供商 |
| 服务商授权（新增） | 服务商 → 工作组/服务专员 的品种×区域授权 | 服务提供商 | 药厂销售部门 |

交互要点：

- 服务商授权页签的表格列：序号、服务提供商、授权对象（类型+名称）、品种、区域、操作；
- 新建/编辑弹窗中「授权对象」的类型由当前链路自动决定，不可手选：四级链选工作组，三级链选专员——用户感知为「对象下拉内容变了」而非「多了一个类型字段」；
- 未授权空状态：说明原因与下一步（「请先把品种授权给执行对象，再进行任务拆分」）；
- 页签角标显示当前授权对象类型（如「当前授权对象：工作组」），让链路形态在授权页可见。

### 4.4 拆包强约束（D7）

拆分任务包弹窗（含三级链的「分配任务量给服务专员」形态）：

- 每行「工作组 / 服务专员」下拉**仅列出**该行所选品种×区域上已授权（`ProviderSubAuth`）的对象；
- 按任务链快照决定用哪一类授权：四级链任务用「→工作组」授权，三级链任务用「→服务专员」授权；
- 多品种/多区域任务：行内切换品种或地区时，下拉选项随之刷新；
- 无可选对象时：下拉为空并提示「该品种·区域尚无授权对象，请先在 品种授权 → 服务商授权 中完成授权」；
- 既有校验保持：拆分明细必须落在任务计划明细内、次数合计不超计划、金额不超计划总金额。

### 4.5 与链路配置的联动规则

| 场景 | 行为 |
|---|---|
| 切到三级链后新增授权 | 只能建「→服务专员」授权 |
| 切回四级链后新增授权 | 只能建「→工作组」授权；此前的专员授权保留不失效 |
| 存量任务拆包 | 按**任务链快照**取对应类型授权，不按当前配置（例：任务创建时为四级链，即使配置已切三级，其拆包仍按工作组授权过滤） |
| 变更记录 | 链路启停在执行链路配置页留痕；授权增删在品种授权页留痕（沿用现有 Toast + 操作记录模式） |

### 4.6 范围边界

- 真实系统的第三层授权（工作组 → 专员）**本期不做**：原型无工作组登录视角，无法演示该操作；列入待定项，待工作组视角立项后补充；
- 不做授权有效期、授权审批流、授权变更版本链（与药厂层授权保持同等深度）。

## 5. 数据模型设计

### 5.1 类型清单（`src/types.ts`）

```ts
// ===== 执行链路配置 =====
export type ChainNodeId = '药厂' | '服务提供商' | '工作组' | '服务专员';

export interface ChainNode {
  id: ChainNodeId;
  level: number;          // 1~4
  label: string;
  optional: boolean;      // 仅工作组为 true
  enabled: boolean;
  summary: string;        // 节点职责一句话（链路图卡片展示）
}

export interface ChainChangeRecord {
  id: string;
  time: string;           // YYYY-MM-DD HH:mm，演示时间基线
  operator: string;
  action: '初始配置' | '启用工作组' | '停用工作组';
  impact: string;
}

export interface ExecutionChain {
  nodes: ChainNode[];             // 固定四节点，顺序不变
  workgroupEnabled: boolean;      // 派生自 nodes，便于判断
  changeRecords: ChainChangeRecord[];
  updatedAt: string;
  updatedBy: string;
}

/** 任务链快照：创建时锁定，只读 */
export interface ChainSnapshot {
  workgroupEnabled: boolean;
  snapshotAt: string;
}

// ===== 既有类型修订 =====
export interface Task {
  // ...
  chainSnapshot: ChainSnapshot;   // 新任务必填；存量 TR-001~TR-010 补默认四级快照
}

export interface WorkloadAssign {
  workGroup?: string;             // 改为可选：三级链任务直挂专员
  // ...
}

// ===== 服务商下层授权（第 4.2 节） =====
export type SubAuthTargetType = '工作组' | '服务专员';
export interface ProviderSubAuth { /* 见 4.2 */ }

// ===== 页面 =====
export type PageId = /* 现有值 */ | 'execution-chain';
```

### 5.2 领域逻辑（`src/context/TaskDataContext.tsx`）

| 能力 | 说明 |
|---|---|
| `chain` 状态 + `updateChain(next)` | 链配置内存态；启停必须写变更记录并刷新 `updatedAt/updatedBy` |
| `splitTask` 链感知 | 四级链保持现状（写 `workgroupSplits`） |
| `splitTaskToSpecialists(taskId, rows)` | 三级链：把品种×地区×业务直接分配给专员，写 `workloadAssigns`（`workGroup` 为空，`progress='未完成'`）；校验复用「不超计划明细 / 不超计划总金额」+ **D7 授权过滤校验** |
| `assignWorkload` 前置校验 | 「请先拆分任务包到工作组」仅对四级链任务生效 |

## 6. 页面与导航

### 6.1 系统管理 → 执行链路配置（新页面）

```text
系统管理
├─ 角色管理
├─ 用户授权
├─ 权限审计
├─ 角色预览
├─ 机构部门（占位，不动）
├─ 操作日志
└─ 执行链路配置   ← 新增
```

页面结构（视觉以已确认预览页为准）：

1. 页头：标题 + 说明（配置仅对新建任务生效）+ 右上角当前链路徽章与最近更新时间；
2. 链路图卡片：四节点横排，仅工作组带开关；停用态 = 虚线边框 + 降透明 + 「已停用」文字标签；连接线文案随形态变化；
3. 职责对比表：任务拆解方 / 工作量分配方 / 组长审核角色 / 发起结算维度（后者两列一致：「服务月份 + 服务专员」）；当前生效列主色浅底 + 「当前生效」标签；
4. 变更记录时间线（倒序）；
5. 底部提示条：「链路调整只影响调整后新建的任务，已创建任务按创建时的链路继续执行」。

### 6.2 品种授权页双页签

见 4.3。服务商登录后进入该页默认落在「服务商授权」页签。

### 6.3 任务执行页联动点

- 列表「分配阶段」列：链感知文案；
- 拆分任务包弹窗：双形态 + D7 授权过滤下拉；
- 任务详情 meta 区：执行链标签（四级链 / 三级链）；
- 任务拆解页签：三级链按专员聚合；
- **不加**步骤条、**不加**新建任务说明行、结算弹窗**不改**（D9）。

| 页面 | 角色 | 动作 |
|---|---|---|

无 `edit` 权限（含角色预览只读模式）时：链路开关禁用并提示「当前角色仅可查看」。

## 8. 演示剧本（验收口径）

1. 以「药厂销售部门」登录 → 系统管理 → 执行链路配置：四级链，四节点生效中，初始变更记录可见；

## 9. 红线与约束

1. 链路只有两态，不发明第三态；不修改手册 7 词状态与既有业务状态语义；
2. 链快照不可变；配置变更不回写存量任务；页面上不存在编辑快照的入口；
3. 不新增步骤条；新建任务弹窗不加链路说明行；发起结算不随链路变化（D9）；
4. 不做拖拽式链路编辑器、多级服务商、药厂直营（无服务商链）、工作组→专员第三层授权；
5. 不新增登录角色、不修改 `Role`/`BizRole`；不删除或重命名任何现有 `PageId`、权限键；
6. 视觉只使用现有 token 与 `lucide-react` 图标；停用态必须有文字标签，颜色不做唯一信息载体；金额全角 `￥`；动效 ≤200ms 并尊重 `prefers-reduced-motion`；
7. 「机构部门」占位项、「药厂业务开关」占位页保持原样不动。
